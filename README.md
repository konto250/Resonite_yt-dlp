# Resonite で Youtube 動画が上手く再生できない場合の対処法を考えてみた

今のところ問題なく再生できているなら、なにも変えることはないので、以下は読まなくていいです。

「なんかガチャガチャやってたら直った」にすこしでも根拠らしきものを与えようとおもい、ここ数日ログとにらめっこした結果です。

n=1 なので、その点だけは注意してください。

---

## 対処法

Resonite の「設定 → ビデオストリーミングサービス → ブラウザの Cookie を使用」を切り替えてみます。

変更する前に、今の設定が何になっているかを見ておいてください。戻したくなったときに必要です。

常用していないブラウザで YouTube にログインし、「ブラウザの Cookie を使用」をそのブラウザに切り替えます。

- Firefox を常用していないなら Firefox が扱いやすいです（Resonite 使用中も開いたまま使えます）
- Chromium 系（Chrome/Edge/Brave/Vivaldi）を使う場合は、Resonite 使用中はそのブラウザを完全に閉じておく必要があります

> **なぜ Firefox が扱いやすいか**
>
> Chromium 系（Chrome/Edge/Brave/Vivaldi）は、起動中に Cookie のデータベースファイルをロックします。この状態だと Resonite が Cookie を読めず、動画が一切再生できなくなります。
> Firefox はロックしないので、開いたままでも問題ありません。
> これは、Firefox の方が yt-dlp のような外部ツールから扱いやすいということです。

Youtube にログインするアカウントは捨て垢がよいかも？（過去に作って普段使っていない Google アカウントとか、ソシャゲのデーター連携のために1個ぐらいそういう垢あるでしょ？）

理由は、YouTube 側が自動アクセスとみなしてアカウントに何らかの制限をかけた場合に、普段使いのアカウントを巻き込まないためです。今回の検証ではそういうことは起きていませんが、念のためです。

一度うまくいっても、そのブラウザでログアウトしたり Cookie を消すと元に戻ります。

切り替えたあと、Resonite の再起動は不要です。動画を2〜3本再生して確認してください。1本で判断すると、たまたま通った／通らなかっただけの可能性があります。

これで Youtube 動画が見えるようになった場合、おそらくライブが見られないとおもうので、ライブみるときだけ「ブラウザの Cookie を使用」を「NONE」にします。

これでうまくいくかは yt-dlp、Resonite のアップデートによって変わります。
